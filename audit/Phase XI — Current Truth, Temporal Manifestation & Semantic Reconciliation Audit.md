> Current Truth is authority-scoped, not globally chronological.

K. Current Truth Must Be a Resolution, Not a Stored Scalar

The research now allows a decisive architectural conclusion.

We should not add:

to every UEM object.

Why?

Because “current truth” depends on the question.

Example:

Therefore:

Current Truth is a computed epistemic view over manifestations, authority, provenance and time.

It is not another stored property.

N. Present vs Historical vs Superseded

We need precise distinctions.

PRESENT

A manifestation demonstrably exists in the current observed state.

Example:

Python implementation at HEAD

AUTHORITATIVE CURRENT

The manifestation currently carrying authority within its epistemic domain.

Example:

APPROVED Canon v2

LATEST

Most recent known manifestation.

Could be:

DRAFT Canon v3

which is not necessarily authoritative current.

HISTORICAL

Previously valid/relevant manifestation retained for traceability.

SUPERSEDED

A manifestation explicitly replaced by another.

DEPRECATED

Still identifiable, but explicitly discouraged/retired according to lifecycle semantics.

OBSOLETE

Coverage semantics indicate it is no longer applicable.

These terms must not be collapsed.

S. Error Memory Is Temporally Different

Error Memory deserves special treatment.

An Error Memory record may say:

Later implementation may fix that failure.

The Error Memory should not disappear.

Its temporal interpretation becomes:

valid historical fact

possibly active

fixed

Therefore:

fixed
≠
forget

This is fundamental for the desired workflow where previously encountered Termux/Bash errors should not recur.

Current Truth should be able to say:

> “The defect no longer exists in current implementation, but the failure remains historically valid and its prevention rule remains relevant.”
